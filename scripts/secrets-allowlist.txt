# MacClean 脱敏扫描备案表（scripts/release.sh 与 --scan-only 读取）
# 格式: scope<TAB>file-or-*<TAB>rule<TAB>reason
# scope: tree=工作区跟踪文件（含 git add 之后的 staged 复扫）  hist=完整 git 历史（含 commit 正文与 tag 说明）
#          text=发版标题（**这一档不接受备案**，见 scan_text）
#
# ⚠ 绝对零命中那一档（私钥 / GitHub token / 细粒度 PAT / AWS / Slack / Google API key）
#   **不接受通配 file**，且 reason 里必须**同时**带两个键：
#     `evidence=<commit 前缀>`  证明"这行是假数据"的提交，必须真实存在且**确实动过这个文件**；
#     `matchsha=<12 位指纹>`    命中处打印的那个 sha1 前 12 位，把豁免钉到**具体那一串内容**上。
#   以前这里写过一行 `hist	*	private_key`，那等于把私钥规则对**全部历史**关掉；
#   而"abs 不许备案"只写在注释里，`report_hit` 先查备案再计数，机器根本不认。
#   后来改成"确切 file + evidence"，仍然漏了一层（2026-10-01 独立复审 P0，实测到）：
#   备案的粒度是 (scope,file,rule)，所以一个文件只要有一条合法备案行，这个文件对该规则
#   **永久整体失明**——后来往同一个文件里贴一把真私钥，扫描器照样打印"✅ 扫描通过"。
#   现在由 `allowlisted()` 强制：通配不生效、缺 evidence 不生效、commit 对不上不生效、
#   **内容指纹对不上不生效**。
# 每条都必须是人工核对过"确实是假数据"的，并写清**凭什么能判假**。
#
# ⚠ 这张表自己也在扫描范围内，所以**理由文本里不许出现任何能被规则匹配的字面量**。
#   上一版把私钥头原样抄在理由里（"同一夹具随提交进过一次历史：`-----…KEY-----`"），
#   于是备案表自己被 private_key 规则命中——一份用来解释"为什么这行不是凭据"的表
#   反而成了凭据，而 abs 一档又要求"证据提交动过该文件"，新文件压根不在任何提交里，
#   证据永远凑不齐 = 门禁自我死锁。描述形状请用文字，指纹用 matchsha，不要用原文。

# 本项目自带凭据检测器（剪贴板与 API Key 两处），它的输入夹具**必须**长得像真凭据，
# 否则测不到检测器。判假依据逐条写明，不是一句"这是测试数据"。
# 夹具本体见该文件的 `sensitiveKeys` 数组：它只是喂给 checkSensitivity() 的字符串字面量，
# 断言的是"检测器会把它标红"，从来没有网络调用、也没有任何一侧能拿它鉴权。
