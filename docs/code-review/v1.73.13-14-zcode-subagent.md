### #1 · P1 · `DiskMonitorConfig` 手写解码没有自检钉住——删掉它全部自检照绿

- **严重度**：P1（假绿：数据-loss 防护零防回归）
- **位置**：`Sources/MacClean/DiskMonitor.swift:71-94`（手写 `init(from:)`）；缺口在
  `Selftest+Unattended.swift`（4 条 trash check 全不碰解码）与全仓自检
  （grep 证实没有任何一条自检解码「缺 `trashAutoEmpty*` 键」的 JSON；持有
  `DiskMonitorConfig` 持久化断言的 `LaunchAgent` / `RiskAndWhitelist` / `GlobalHotkeyDeep` /
  `SystemAndHistory` 各条全是「先 encode 自己的输出再 decode」，永远写全键，结构上测不出缺键场景）。
- **症状**：手写 `init(from:)` 本身正确（21 个字段逐条 `decodeIfPresent ?? 默认`，默认值与属性默认
  逐字段核对一致，见下「已检查」）。但它是本轮声明目标之一（scope.md：「老配置数据缺新键，
  合成 Codable 会整份解码失败重置用户设置」），却没有一条断言证明它挡住了那个场景。
- **为什么是问题**：将来任何重构把这段手写解码删掉（合成 `Codable` 回归），老用户的整份配置
  会在下一次解码时被静默重置成出厂值——而全部自检仍然全绿。独立探针已证实：同形最小 struct
  用合成 `Codable` 解码一份只含老键的 JSON 会抛错（decode 结果为 nil，走 `load()` 的
  `DiskMonitorConfig()` 重置分支）。这正是 RELEASE-CHECKLIST §1「改动了持久化结构时：确认新增字段
  不会让老数据解码失败」要防的事故；同仓 `WhitelistManager` 有先例
  （`Selftest+RiskAndWhitelist.swift:308`「新增未知字段不会毁掉老数据（前向兼容）」），
  本轮没有照办。
- **建议动作**：补一条自检：构造只含 v1.73.13 时代老键的 JSON（或 encode 后手动删掉两个
  `trashAutoEmpty*` 键）→ `JSONDecoder().decode(DiskMonitorConfig.self:)` 不抛错，且全部 21 个字段
  等于属性默认值。顺带钉「手写解码的 `?? 默认` 与属性默认值一致」——现在两者是两份字面量，
  存在漂移空间（改属性默认值不改解码默认值时，老数据用户与新装用户拿到的行为会分叉）。

### #2 · P3 · AppUpdateScanner 的 G18 修复无断言钉住（修法本身复核为语义等价或更严）

- **严重度**：P3
- **位置**：`Sources/MacClean/AppUpdateScanner.swift:85-88`；8 条 AppUpdate 自检
  （`Selftest+Foundation.swift`）均未覆盖此分支。
- **症状**：`hasPrefix("/System/")` 换成 `FileSystem.isSystemProtected(path)` 是**正确的修法**
  （走 G8 唯一判据：`normalizePath` + `guardSystemProtected` 全表，`FileSystem.swift:1144-1151`）。
  语义等价性逐条核对：①`/System` 子树照旧全排除（`GuardPath.matches` = 精确或任意子层级，
  `FileSystem.swift:1061-1073`）；②新增排除 `/Library/Updates`、`/private/var/vm`、`/private/var/db`、
  `/private/var/folders/zz` 四个根——这些位置不存在用户安装的 App，对「过滤系统 App」这个用途
  是无害的加严；③旧写法不排除恰为 `/System` 的路径、新写法排除，也是加严。**没有任何一处在
  旧判据下被排除、新判据下放行**，不存在放松。
- **为什么是问题**：8 条 AppUpdate 夹具全部在 `/private/tmp`，没有喂过 `/System` 或
  `/private/var/db` 样本；而 `AppInventory` 的默认根本身含
  `/System/Library/CoreServices/Applications`，该过滤在每次真实扫描都会执行。若有人把它改回
  字符串护栏，自检不会红，系统 App 会重新出现在更新列表里（UI 正确性问题，非安全问题，故 P3）。
- **建议动作**：补一条断言：`snapshotOverride` 喂 `/System/Library/CoreServices/Applications/Foo.app`
  与 `/private/var/db/Foo.app` → `scanInstalledSources()` 不列二者（`/private/var/db` 是判别性样本，
  只有新实现排除它）；再配一条源码形状或直接依赖既有的 G18 全仓 lint 把 `AppUpdateScanner.swift`
  登记进活性锚。
