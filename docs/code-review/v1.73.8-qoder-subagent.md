## 不采纳及理由

**P2-6 自定义根被 G8 拦下时的"三无状态"本轮不补**：二次复审 P2-6 建议加 `blockedProtectedRoots` 通道 + 面板顶栏措辞。本轮**不做**，理由：
1. **生产不可达**：`customDirectory` / `customDirectories` 在这 4 个模块的唯一调用方是自检（`DownloadsOrganizerCard` / `ScreenshotsOrganizerCard` 里没 fileImporter/NSOpenPanel，QuickLook 卡片只调 `scan()` 无参），用户从界面无法构造这个入口。
2. `RELEASE-CHECKLIST §"给复审指出的缺陷写自检之前先证明那条分支可达"` 明确写了这条规矩——不可达就不硬造自检/通道。
3. 转待议 5，等"自定义根扫描"这条 UI 真做出来时（那是 P2 治理模块级工作），把 `blockedProtectedRoots` 一并做掉。

**P2-4 QuickLook `isCustom` 分支的自检覆盖本轮不补**：理由同上——需要给 `getDarwinUserCacheDir()` 加 `darwinUserCacheDirOverride` 注入缝，那是新的 API surface；且要构造的形状（uid 0 下 `C/com.apple.QuickLook.thumbnailcache` 落在 `/private/var/folders/zz/…`）本机跑不了 root。转待议 4。

## 待议（不阻断本轮）

1. `FileSystem.guardNever`（`FileSystem.swift:969-970`）与 `CleanPaths.systemProtected`（`CleanPaths.swift:33-40`）是**两份** SIP 清单——本轮新立的"别自己复制清单"通用教训的存量部分。合并成一处声明。
2. G18 的正向"字面哨兵"（`mustBeThere` 每文件必须含 `FileSystem.isSystemProtected(` 字符串）能被"死代码里塞一个 `FileSystem.isSystemProtected(`"绕过；同族问题在 v1.73.6/v1.73.7 立的三条全仓 lint 上都存在。改造方向：**自探针**——lint 内部对一段合成代码跑同一判据并断言**必须命中**，命中不了就判红；比"字面存在性"强得多。
3. 扫描侧 `isSystemProtected(path)` 只做 `normalizePath`，删除侧多做 `realPath`——软链根被扫描放行、被网关拒绝，不构成误删但"扫描侧统一到 G8"这句话在软链场景下不完全成立。下一轮统一。
4. QuickLook 的 `isCustom` 分支需要 `darwinUserCacheDirOverride` 注入缝 + 形状断言，默认候选走 uid 0 段时 `scan()` 仍列条目、自定义根走 SIP 时被拦。
5. 自定义根被 G8 拦下时的"三无状态"——等"自定义扫描根"UI 真做出来时补 `blockedProtectedRoots` 通道 + 面板措辞。
6. `stripSwiftComments` 长期看要么写成真正的 tokenizer、要么 lint 侧改成按括号/字符串状态机匹配；本轮之后它已经承载 4 条全仓 lint 的判据正确性。已知脆点：`let s = "https://x/y" // was hasPrefix("/System")` 会让引号奇偶保护把整行不剥、注释里的 needle 被当代码 → **假红方向**，仓库当前无此形状。
7. `/Applications` 一族（`ScreenshotsOrganizer:72` 保留、`OrphanScanner:327` `contains("/Applications/")` 等 3 处业务判据）与"扫描根不该在这"的策略性 vs "SIP 硬保护"的安全护栏的字面分界，需要在文档里明确，别让 G18 的口径继续靠注释解释。
