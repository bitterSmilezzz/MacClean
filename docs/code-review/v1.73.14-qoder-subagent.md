## 待议（不当轮修）

- **#20 pending 与废纸篓现状对账**：清空废纸篓 / 放回原位时把历史记录里的 pending 结转成已落盘，
  否则"累计释放 + 另有 X 未释放"这两个数会随时间互相否定。需要一条新的状态结转，
  并顺带统一 `HistoryView` 的列头/行值/页脚三处口径（复审 P2-10）。
- **归档/迁移是否纳入"落点分账"体系**：它删的是原件、留的是压缩包，净变化是 `压缩包 − 原件`，
  与清理的"这批字节去了哪儿"不在同一轴上。本轮只把话说准（不再承诺"立即释放"），
  没有把它塞进 `SpaceDisposition`——`savedBytes` 不是"搬进废纸篓的字节"，硬套会让类型说谎。
- **`claim()` 是否该接受 `cleanedCount`** 以便在零字节时自己说清"清掉了 N 项但没量到字节"，
  而不是依赖调用方的计数分支。本轮用"只报 `0 B` + 调用方补计数"解决，先不动签名。
