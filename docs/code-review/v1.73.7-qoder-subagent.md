## 不采纳及理由（第二轮之间作者与 reviewer 的实质分歧）

**nil 分支记账的自检缺失**（第二轮 P1-A 的可测性延伸）：reviewer 建议给 CLICache / QuickLook / Spotlight 三处 nil 分支都补自检。本轮**不补**，理由：
1. macOS 上 owner 对 mode 000 目录调 `FileManager.enumerator(at:)` **实测**返回非 nil 的枚举器 + 立即走 `errorHandler`；nil 分支在这台机器上不可达。同族 `FileSystem.measureDirectory` 的 nil 分支作者自己也在注释里承认"实测近不可达，所以**不配自检**"。
2. 硬造自检意味着把 `enumerator(at:)` 换成一个能返回 nil 的私有 seam——那要么把 `FileManager` 抽象出来（跨模块大改），要么用 mock（"会自改的 fake"是 `MEMORY: feedback-test-quality-smells` 列出的假绿信号之一）。
3. 判据本身靠代码同族与 lint 保证（`grep` 层面 nil 分支只有 sibling 那一种正确写法），比自检更便宜也不误伤。

## 待议（不阻断本轮，交下一轮）

1. **`FileSystem.size(at:)` 不返回 readable**：`incompleteWalks` 只用来挡缓存，Scanner 里其余 ~38 处 size 消费方拿不到残缺信号，DevProject/LoginItem/FontCache 的默认勾选都在这一族。建议单独一轮把 `size(at:)` 也 `readable` 化。
2. **三张卡片的 UI 措辞**：残缺项行内加"体积为下限"或锁形图标 + Summary 级不完整条；对齐 v1.73.4 归档面板的三态措辞。P1-E 的完整收口。
3. **`QuickLookThumbnailPurger.swift:135` 的 `path.hasPrefix("/System")` 字符串护栏**：与 G14 冲突，**不在本轮 diff 内**但本轮动过这个文件；记账。
4. **SpotlightStoreItem.readable 默认 true** 的语义反常（"权限不足、根本不可读"的卷项 `readable=true`）：本轮靠 `status != isOrphanOrCorrupted` 挡着，但语义上应翻默认或让卷项显式传 false。
5. **同族 `isSelected: Bool = true` 默认还剩三处**（LoginItem / DevProject / FontCache）：与 P1-3 同族，但配套 `size(at:)` 没有 readable 通道，翻默认只是把风险挪位置。跟 P1 待议 1 一起处理。
6. **`selectedCount` 与 `selectableCount` 的口径冲突**：用户手勾残缺项后全选按钮卡死；建议 `selectedCount` 也走 `readable` 口径。
7. **新自检的 `resetDeniedAccess()` 不在 defer**：当前不致假红（读快照的两个套件都在前面），但挪顺序会串味；对齐同文件的 sibling 用 `defer` 写法。
