## P2 及处置

- **已修**：`usage(of:)` 注释里对已删除函数的引用；`AppLocalizationScanner` 残留的双空行；性能自检里 150×60 的死夹具与自相矛盾的旧注释。
- **转待议**：
  1. **4 处重复的递归求体积实现**（`CLICacheScanner.calculateDirectoryStats`、`SpotlightScanner`、`AudioHALScanner`、`PrinterDriverScanner`）仍省略 `errorHandler:`，含 mode 000 子目录的树会静默返回偏小值且不记盲区。迁移要逐模块判口径，不硬塞本轮。
  2. **已落盘的残缺值不做迁移**：新规则只挡新写入，v1.73.4 及更早写进 `scan_incremental_cache.json` 的部分值仍会被复用最长 7 天。修法是最省事的换缓存文件名（`_v2`）或对 `size == 0 && isDirectory && exists` 的旧条目做一次过滤；注意清单里"Swift 合成 Codable 不吃默认值"那条。
  3. **`incompleteWalks` 名字会误导**：20 万条目截断也被标进去，于是最大的几棵树整体退出跨会话缓存（方向没错，代价与语义被文档说成"权限挡过"）。建议拆成 `enum WalkDefect { case denied, truncated }`。
  4. **指纹描述不准**：注释写"lstat + 顶层子项数"，实现还含 readdir 顺序前 ≤50 项的 mtime 之和 → >50 子项时深一层改动可能不变指纹，旧值复用 7 天。
  5. **`FileSystem.swift` 注释引用了错误的 §**（写成 §7.2 硬保护，应为 §7.3 读不到≠空）。
  6. **`resourceValues` 单条目失败静默少算**（`guard let values else { continue }`）未标记为残缺。

## 明确核查过、未发现问题的方面

- **删除链路与护栏未被触碰**：`ResidueDeletionGate` / `Cleaner` / `journal` 参数无改动；新增的 `bundleSize` 调用只填展示字段，未进入任何"能不能删/默不默选"的判据；`FontCacheInspector` 的 `size > 0` 门槛在新口径下只会变严不会变宽。

- **`incompleteWalks` 不泄漏**：insert 与 measure 侧的取出按键对称，另有 `beginMeasurementSession` 兜底清空。
- **锁**：`errorHandler` 取 `measurementLock` 时调用方已 unlock，无 NSLock 重入死锁；`deniedLock` 仍独立。
- **PII**：新自检夹具全在 `/private/tmp` + UUID，失败输出只打印数字与条数。
- **计数**：README 611 与实际 `自检完成：611 通过 / 0 失败` 一致。
