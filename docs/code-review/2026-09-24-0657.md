### P1 — 重要

- **`Sources/MacClean/Scanner.swift:452` / `:586` / `:1448`（`recordBlindSpotIfNeeded` 的三个调用点）** — 把探测默认值翻成 `false` 之后，扫描**不再跳过**读不到的目录，而是紧接着去打开它；真机卡死若由该目录访问触发，则卡死点只是从探测的 `opendir` 移到枚举器
  - 为什么是问题：三处调用点的形状都是 `guard !FileSystem.recordBlindSpotIfNeeded(at: X) else { continue }`，紧跟一行 `FileSystem.size(at: X)`。`recordBlindSpotIfNeeded`（`FileSystem.swift:207-215`）在探测关闭时**首行即 `return false`**，于是 `continue` 永远不会执行 —— 语义从「读不到 → 记盲区 → **跳过**」退化成「不记 → **照常往下走**」。而 `size(at:)` → `measure` → `computeMeasurement`（`FileSystem.swift:349` 起）在目录分支用的是 `FileManager.enumerator`，**同样会 `opendir` 同一个路径**。注释（`FileSystem.swift:220-236`）说失败只退化成"盲区少报几个"，但实际还多了一件事：**探测的跳过语义一并没了**，所以对受保护目录的访问次数不是减少，而是从「探测 1 次」变成「枚举 1 次」。真机观察记录的是"停在 `open()` 上"——而 `FileManager.enumerator` 内部的 `opendir` 在栈里同样显示为 `open()`，因此无法仅凭栈帧区分是探测还是枚举器。若卡死源于目录访问本身（模态框会阻塞发起访问的进程），那么下一个调用点仍在同一循环的下一行。
  - 建议：让「要不要碰受保护目录」成为**一次判定同时门禁两个调用**，例如探测关闭时把整条候选直接跳过（恢复 `continue` 语义），而不是只让 `recordBlindSpotIfNeeded` 空转；或把该判定收进一个 `FileSystem.shouldTouchProtected(_:)` 由两处共用。**验证方式**：按你自己记录真机卡死的方法复跑一次 `--scan`——若栈仍停在 `computeMeasurement` 一侧，说明本条成立。若你手上那次的栈帧明确是 `canOpenDirectory`（而非 `computeMeasurement`），请把栈贴进本目录，本条即可关闭。
  - 附带：`computeMeasurement` 的枚举器失败分支**自己**也会 `recordDeniedAccess`（`FileSystem.swift` 内 `isPermissionDenied` 判断），`children(of:)` 亦然。所以「盲区记账」并非只靠探测——把默认值关掉并不会让盲区清单整体失效，但也意味着**探测的独立价值只剩"提前发现"**，代价却是丢掉跳过语义。

- **`Sources/MacClean/DownloadsOrganizerCard.swift:389-404` 与 `Sources/MacClean/ScreenshotsOrganizerCard.swift:401-416`（`executeArchive()`）** — 归档路径写历史但不触发刷新（**上一轮 P1 残留，本轮未修**）
  - 为什么是问题：`onTriggerClean?()` 在这两个卡片里各自只有一处调用点，都在 `executeClean()`（`DownloadsOrganizerCard.swift:384`、`ScreenshotsOrganizerCard.swift:396`）。而归档同样写历史：两条 `executeArchive()` 都经 `recordArchiveMove` 落到 `HistoryStore.append`（`mode: "归档移动"`），完成回调里却只有 `loadData()`。结果：用户点「智能归档」→ 记录**已落盘** → `AppState.history` 停在旧值 → 切到「清理历史」页看不到这条「归档移动」，侧栏计数也不变，直到下一次别的清理或重启。无数据丢失（盘上是全的），故定 P1。
  - 建议：在两个 `executeArchive()` 的 `DispatchQueue.main.async` 块里补 `self.onTriggerClean?()`（与 `executeClean` 对称）。更彻底的做法是让 `recordArchiveMove` 那一层统一发 `NotificationCenter` 通知、由 `AppState` 订阅刷新——现有写法每加一条写路径就要在 UI 侧手工配对一次，这次的漏配正说明该约定靠人记不可靠。另建议把 `Selftest+SystemAndHistory.swift` 那条自检扩成「逐个写入口写一条、断言 `refreshDisk()` 后都可见」。
