## 待议（设计级 / 跨文件 / 属产品决策，未在本轮动）

1. **P2-10 性能阈值的口径**：探测自 v1.73.3 起每次要多一趟 GCD 跳转，`ratio < 0.5` 这个上界是
   按"3 个 syscall"定的，如今分子含调度开销，冷队列下可能抖动假红。两个方向：把阈值放宽到
   与 dispatch 抖动同数量级，或改断"探测次数 == body 次数"这类与调度无关的量。
   本轮实测该条仍绿（比值未撞阈值），所以先不动，但清单里已挂着一条同型的 TSan 假红待议。
2. **P2-11 超时与权限拒绝共用一种盲区类型**：`ScanIssue.Kind` 已有 `.unreadable`，
   但 `noteDeniedRoot` 只有一条通道、`deniedAccessSnapshot()` 只返回 `[String]`，
   要分家得给盲区加 reason 字段并改 UI 文案——跨 `FileSystem`/`Scanner`/`CategoryDetailView` 三处，
   属产品口径决策（"5 秒没读到"要不要跟"没权限"分开告诉用户）。
3. **P2-12 归档刷新的行为级自检**：`executeArchive()` 真的会把文件移进 `~/Downloads/Archived_Downloads`，
   做行为断言要先造一个可注入的归档根；同类的"治理卡片行为断言（v1.72.1）"已有先例，
   但需要给两张卡片开 fixture 目录的缝。
4. **`proactiveBlindSpotProbe` 是否该退休**：P1-1 修完后，三处候选目录的跳过判定已不受该开关管，
   它只剩"要不要**额外**多开一次做记账"这一点作用，而那次额外开在 `canOpenDirectoryBounded`
   里本来就有截止。审查者认为这个开关的原始理由（防挂死）已被 deadline 取代。
   退休它要动 `AppState`/`AutoCleanService`/`MacCleanApp` 共 5 个赋值点与 2 条自检，属跨文件设计决策，
   本轮按"最小正确修复"保留现状。

**M8 值得记一笔**：先写的那条是**行为**断言（8 个线程起跑屏障问同一个卡死 key，断 body 只跑一次）。
把实现改成 check-then-act 之后它**照样全绿**——窗口只有几条指令，实测 8 个线程仍然只跑 1 次 body，
行为断言分辨不了原子性。于是补了一条**形状**断言（占位那一行不许自带 `wedgedLock.lock()`），
M8 才转红。教训：**"并发下只发生一次"这类断言在窗口极窄时是不可证伪的**，
要么把不变量写成代码形状钉住，要么就别声称钉住了它。
