### P1 — 重要

- **`Sources/MacClean/Selftests/Selftest+DownloadsOrganizerDeep.swift`（新增的"全仓不得再有 `errorHandler` 为 nil 的递归求体积"）** — 这条不变量只匹配**字面量** `errorHandler: nil`，而"省略 `errorHandler:` 参数"是 `FileManager.enumerator` 的默认值、语义逐位相同，却全部放行。实测产品源码里有 **4 处递归求体积**正是这个形状：
  - `Sources/MacClean/CLICacheScanner.swift:236`（`options: [.skipsHiddenFiles]`，之后 `var totalSize` + `totalSize += s`）
  - `Sources/MacClean/SpotlightScanner.swift:389`（`totalSize += Int64(values.fileSize ?? 0)`，返回 `(totalSize, fileCount, latestMTime)`）
  - `Sources/MacClean/AudioHALScanner.swift:656`（`totalSize += Int64(values.fileSize ?? 0)`）
  - `Sources/MacClean/PrinterDriverScanner.swift:654`（`totalSize += Int64(values.fileSize ?? 0)`）

  - 为什么是问题：同一个提交刚以"`errorHandler: nil` 的语义就是第一个错误就停止遍历且不报告，于是『有一半没读到』与『真的就这么大』结果一样"为由，删掉了 `AppLocalizationScanner.directorySize`（实测一个含 mode 000 子目录的树返回 **0**）。但这 4 处调用的默认 `errorHandler` 同样是 nil，行为完全一致，只是写法上省略了参数——lint 抓不到，README 与发版清单里"产品源码里一处都不许有"这句因此**不成立**。失败方向是"谎报"，而本项目把"谎报优于漏报"倒过来排在第一位。
  - 建议：把 lint 从"匹配字符串"改成"检查调用点有没有传 `errorHandler:`"（对 `enumerator(` 做一次到配对右括号的参数扫描，缺失即违规；`errorHandler: { _, _ in true }` 这类"忽略错误"形态也应一并要求改走 `FileSystem.size` 或记账）。同时把这 4 处收敛到 `FileSystem.size`，或补上会 `recordDeniedAccess` 的 `errorHandler`。
  - 注：`ColorSyncScanner.swift:290`、`DuplicateScanner.swift:481` 传的是 `errorHandler: { _, _ in true }`，不会被现有 lint 判红；它们不中断遍历，但**静默吞掉错误**，与"盲区要记账"的项目口径也不一致，建议同批处理。

### P2 — 建议

- **`Sources/MacClean/Selftests/Selftest+DownloadsOrganizerDeep.swift`（新增的"面板给 .app 求体积时，走不通的子目录必须记成盲区"）的反证段** — 第二段断言"可读的子目录不该被记成盲区"时，**没有让缓存失效**：第一段已经对同一批路径跑过一次 `DownloadsOrganizerScanner.shared.scan(customDirectory: root)`，`FileSystem.measure(at:)`（`:557`）会把结果写进 `measurementCache`；第二段只调了 `FileSystem.resetDeniedAccess()`（它只清 `deniedRoots`），随后再扫同一路径会**命中缓存直接返回**，根本不进 `children(of:)`，自然也不会记盲区。
  - 为什么是问题：反证会因缓存命中而通过，而不是因为"权限已恢复、可读的子目录不会被误记"。这条自检的正向段（拒绝项必须记盲区）是有效的，但反证段目前守不住"没拒绝就不许报"这一半。
  - 建议：第二段前加 `FileSystem.invalidateMeasurements(for: [app])`（或 `beginMeasurementSession()`），让反证真的走一遍遍历；也可把第二次扫描换到一条新路径，避开缓存。
  - 不确定项：我未运行自检（只读约束），上述结论由 `measure` 的缓存命中分支静态推演得出，**非实测**。

- **`Sources/MacClean/Selftests/Selftest+Performance.swift`（性能自检）的 fixture 里有 9000 个文件已成死重** — `paths`（150 个目录 × 60 个文件）现在只被一处使用：`recordBlindSpotIfNeeded(at: paths[0])`。性能测量已改用新建的 `sparse` / `dense`（40×1 / 40×300 条目，在顶层）。而该 fixture 上方的注释仍写着「每个候选目录放 60 个条目：让"读一遍顶层"与"只开一下"的代价差暴露出来」——描述的是已废弃的 1:60 口径。
  - 为什么是问题：每条自检要创建约 21000 个文件（150×60 + 40×301），其中 9000 个只为了 1 次断言；自检时长的主要来源就是建文件，而注释会误导后来者以为那 60 条目还参与判据。
  - 建议：`paths` 缩到 1 个目录（或直接复用 `sparse`），并同步改掉那句注释。

- **`Sources/MacClean/FileSystem.swift:413`（`recordBlindSpotIfNeeded`）仍用 `lstat` 判类型，与同一文件里 `probeDirectory` 的显式结论相矛盾** — `probeDirectory`（`:343`）的注释写着：「判类型必须用 `stat`（**跟随软链**）而不是 `lstat`：…用 lstat 判会让一个软链形态的缓存目录直接被判成"不是目录、不用探测"而放行，恰好绕开这套机制存在的唯一理由。」而 `recordBlindSpotIfNeeded` 的守卫正是 `lstat(path, &st) == 0, (st.st_mode & S_IFMT) == S_IFDIR`。
  - 为什么是问题：影响有界——3 个调用点（`Scanner.swift:458/593/1456`）后面都紧跟 `isReadableWithDeadline`（走 `stat`），软链情形会被第二道拦住；但①同一文件里对同一件事给了两条相反的判据，②这个函数还被性能自检直接当作"探测能力"的代表来量（`Selftest+Performance.swift:390`），它的语义与注释相悖会持续误导。
  - 建议：把 `lstat` 换成 `stat`；更彻底的做法是删掉这里的类型判定，直接委托 `probeDirectory`（它已返回三态，要 Bool 时取 `== .readable`），让"该用什么原语"只有一处定义。

- **`Sources/MacClean/FileSystem.swift:164-166`（`noteDeniedRoot`）在迭代 `deniedRoots.keys` 的同时删除元素** — `for existing in deniedRoots.keys where existing.hasPrefix(path + "/") { deniedRoots.removeValue(forKey: existing) }`。
  - 为什么是问题：目前**是安全的**——`Dictionary.Keys` 视图持有旧 buffer，写时复制会让迭代继续跑在旧快照上。但这是靠语言实现的巧合而非意图，且同一文件里 `deniedAccessSnapshot()`（`:191`）处理同一件事时用的是 `let all = Array(deniedRoots.keys)` 先取快照——一处显式、一处隐式，读代码的人无法从写法上判断作者知不知道这一点。
  - 建议：改成 `for existing in Array(deniedRoots.keys)`，与 `deniedAccessSnapshot` 统一。

## 已核实、不构成问题的点

- `probeDirectory` 的三态返回与 `childrenBounded` 的 `nil` / `[]` 区分（`:343`、`:376`）：`nil`＝没看清（盲区或没顾上）、`[]`＝确实是空，调用方 `?? []` 只用于"跳过"决策，未拿它生成用户可见文案。与 `isReadableWithDeadline` 注释里"只许用于跳过这一种决策"的约定一致。
- 盲区记账的路径归一化：三处入口（`readWithinDeadlineDetailed` 的 `key`、`probeDirectory`、`recordDeniedAccess`）**都**先过 `normalizePath`，与 `deniedAccessSnapshot` 的过滤（`isSystemProtectedNormalized` / `isHardExcludedNormalized`）口径一致，不存在"记了但过滤不掉"的错位。
- `Scanner.swift:1662` 的 `~/.Trash` 用 `childrenBounded`：注释称它"在 `CleanPaths.tccProtected` 在册"，实测 `CleanPaths.swift:49` 确有 `"~/.Trash"`。注释属实。
- 性能判据换成"同负载缩放比"（`Selftest+Performance.swift:401`）：`pDense / pSparse < 3.0`，两侧在同一时刻同负载下量、各取两次的 `min`，负载对分子分母同比例作用。判据设计本身站得住；且它确实显式打开了 `proactiveBlindSpotProbe = true`（`:334`），不会退化成"分子恒为 0 的假绿"。
