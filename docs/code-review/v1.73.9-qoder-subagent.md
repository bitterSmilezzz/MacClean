## 不采纳及理由

**P2-3 `.zip` 两处独立字面 → 本轮不修**：`.zip` 的 UI/服务两处字面确实同族，但影响方向是"UI 关得比服务更严"（`.zip` 冷文件被 UI 一起关掉迁移入口），与 G19 打的"UI 开放 / 服务拒绝"方向**相反**、且不会导致误删。要修需要拆 `canArchive` 与 `canMigrate` 两个属性、给 `.zip` 节点的迁移补反证——是 UI 结构改动，值得单独一轮，塞进本轮会把"UI 判据与服务同源"的收口主题稀释。转待议 1。

**P2-4 `/Volumes` 分支不查存在性 → 本轮不修**：UI 侧 `isPhysicalItem` 已经在外层兜住；服务侧被别的调用方（如果有）直接使用时是否需要更保守，属"服务判据本身"的产品决策，与"两侧同源"是两件事。转待议 2。

## 待议（不阻断本轮）
